Capacity study execution notes

An initial worker was interrupted after independent code review identified two diagnostic issues: the solver configuration specified 16 contexts while the implementation used 8, and the Jacobian probes varied time at a fixed state instead of using the corresponding interpolation point. The finalized runner uses the configured 8 solver contexts and the appropriate x(t) for each Jacobian probe. The training settings and the matrix of 36 fits did not change.

Clarification to the frozen protocol's shorthand "partially trained": the initial worker reached 12,000 updates by the time its interrupt arrived. It had generated test windows and begun the prediction pass. It had not written a scored run record or displayed test metrics. Its traceback is preserved in pre-audit-interrupted/worker.log. The diagnostic corrections came from code review, not observed test performance. The run restarted from scratch with the same fixed data and optimization seeds. Thus test data were accessed during an interrupted software pass, but no test outcomes informed a setting. The initial manifests, configurations and checkpoints remain outside the scored run paths and are excluded from analysis.

The protocol is a historical plan protected by the manifest. Its original bytes remain unchanged so the default resume command continues to pass its provenance guard. This execution note explicitly corrects the historical shorthand; an adjacent copy is provided as docs/followup_capacity_execution_note.txt. The finalized numerical code and configuration remain unchanged.

The initial finalized schedule assigned draws 607041 then 707041 to one worker, and draw 807041 to another. They wrote separate draw directories and shared read-only source code and configuration. The final draw was subsequently partitioned as described below. Parallel MPS contention affects elapsed time. Aggregate wall time should be distinguished from the sum of worker runtimes. The 6,000- and 12,000-update checkpoints are validation-selected prefixes of one 12,000-update trajectory; they are correlated evaluations, not separate trainings.

Software smoke runs use data seed 907041 and 100/200 updates; the CPU unit smoke uses 2/4 updates. They are excluded from scored counts. Their earlier manifest reflects preliminary diagnostic code. Only the root manifest and the root matrix of 36 fits define the finalized study.

The final draw was repartitioned for runtime efficiency. Only the waiting shell was suspended, leaving the training child running. This prevents its automatic launch of all draw-707041 cells. After the first two draws finish, separate workers will process draw 707041 with disjoint --kernel rbf and --kernel ou filters. No numerical code, data, optimization setting or completed fit changes. The stopped shell will be removed only after its training child exits.

That orchestration session therefore reports exit 137; it does not represent a failed training fit. The independent 807041 worker exited normally with code 0.
